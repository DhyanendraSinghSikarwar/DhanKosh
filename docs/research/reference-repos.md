# Reference repos: what we took and why

Date: 2026-10-21. Objective: a maintainable Flutter rebuild of Hisaab with the Kotlin app's working behaviour, built on a structure that agents and humans can change safely. Decision record: [ADR-0007](../adr/0007-project-structure-from-reference-repos.md).

## Sources

- `aaronified/fluenough`: Flutter language-learning app, 2000+ files, heavy agent-driven process.
- `DhyanendraSinghSikarwar/hisaab_apk`: the Kotlin app, v2.9.8. 497 files, modules `parser-core`, `shared`, `email`, `app`.

## fluenough: item by item

| Item in fluenough | Verdict | Our version |
|---|---|---|
| `CLAUDE.md` + `AGENTS.md` (map) | Adopt | CLAUDE.md = rules, AGENTS.md = map and top-3 invariants |
| `docs/adr/` numbered, immutable | Adopt | 0000 template + 0001-0007 |
| `docs/plans/` proposals | Adopt, smaller | Only for ideas not yet features; features use `memory/` |
| `docs/research/` | Adopt | This folder |
| `docs/mockups/` + rules | Adopt | README with rules; no mockups yet |
| `docs/screenshots/` | Adopt | Flutter-app screens; Kotlin reference GIFs stay in `assets_reference/` |
| `tools/` Python checks run in CI ("a rule aimed at parallel agents cannot rest on a checklist box") | Adopt | `check_memory.py`, `check_architecture.py` |
| `.github` PR/issue templates, CI | Adopt, trimmed | CI = docs checks, analyze, test, debug APK artifact |
| `CHANGELOG.md` per-PR line | Adopt | Same |
| `.claude/skills`, `.claude/agents` | Already had 9 skills; add `adr` skill and `architecture-reviewer` agent | |
| Release workflow (bump, tag, build) | Defer | Needs signing secrets; tracked in [feature 32](../../memory/32_release_pipeline.md) |
| Never run tests locally | Reject | We run them: no CI-only loop for a solo owner on a phone-first workflow |
| Docs straight to main | Reject | Solo repo today; revisit when there are contributors |
| `android/` generated by `flutter create` in CI | Reject | We commit `android/` because of custom Kotlin channels and permissions |
| Decks, languages, TTS tooling, model-per-job quotas | Not relevant | Different product / personal workflow |
| License GPL-3 + store exception | Defer | [ADR-0006](../adr/0006-licence-and-distribution.md) |

## hisaab_apk: what to keep

| Idea | Keep? | Note |
|---|---|---|
| `parser-core` as pure, corpus-tested module | Yes | Becomes pure-Dart parsers with the same corpora (parity gate, plan.md section 11) |
| "New parser behaviour gets a test from a real message" | Yes | Masked fixtures only |
| Layered modules `parser-core` / `shared` / `email` / `app` | Replace | Feature-first Clean Architecture; the Kotlin split put DB, repos and insights in one `shared` module, which is the structural pain |
| Single ledger write path, dedup by ref, hash, window | Yes | Unchanged ([07](../../memory/07_dedup_review.md), [08](../../memory/08_transactions_ledger.md)) |
| `doc/PLAN.md` request log | Replace | Feature memory files with Change Logs |
| `FEATURES.md` user-facing description | Keep idea | Generated from memory later if needed |
| Windows/OneDrive mirror build | Drop | CI builds instead |
| Plain Room DB | Replace | SQLCipher ([ADR-0003](../adr/0003-sqlcipher-encrypted-db.md)) |
| Logos (Simple Icons, CC0), `lang/` packs | Reuse | Licence check is plan.md open question 4 |

## Conclusion

fluenough contributes enforcement (ADRs, CI-run checks, templates); hisaab_apk contributes behaviour and corpora. Where they differ, the deciding test was: does it keep behaviour parity while making a change touch one place?
